# 安全加固与部署须知

## 云端公开表告警：必须由项目所有者处理

代码更新不会改变 Supabase 项目 `aietizthbhsvnwwkuddz` 的线上权限。
当前环境只有客户端公钥，没有项目所有者权限，未读取、修改或验证生产数据。

1. 若暴露仍在持续，先在项目控制台限制 Data API 访问，保留私有备份和访问日志。
2. 在正确项目的 SQL Editor 中执行 `docs/sql/rls_security.sql`。
   此脚本保留数据、替换白名单表的旧策略，并启用、强制 RLS。
3. 执行 `docs/sql/verify_rls.sql`。它切换到真实 anon 角色，用随机测试记录验证
   无请求密钥、跨账号读写及修改所有权被拒绝，最后回滚测试记录。
4. 在 Security Advisor 中重新扫描；自定义表名及其他公开表需要单独审查。
5. 按可能泄露处理旧访问密钥、任务明文及其他可读取的凭据。RLS 不能撤销已泄露的
   访问密钥。云同步的密文绑定账号标识，不能只在 SQL 中重命名 `user_key`；应先
   备份，再在持有正确主密码的客户端迁移、重新加密。

详细的部署、验证和事件响应见 `docs/SUPABASE_SECURITY.md`。
当前 `x-workplan-key` 是 bearer secret，而不是经过 Supabase Auth 认证的用户身份。
知道该密钥的人仍能构造请求；长期应迁移至服务端验证的用户身份、JWT 和服务端限速。
客户端禁止使用会绕过 RLS 的 `service_role`、`sb_secret_` 等管理密钥。

## 主密码尝试防护：不再自动删除数据

- 旧版“绝对防护”和未完成的自动删除任务在升级时停用，需在设置中重新明确选择。
- 默认关闭额外冷静期，可选“仅冷静”或“第11次失败起关闭本机 PIN/生物识别”。
- 第6次失败冷静5分钟，第7次10分钟，第8次起每次30分钟；正确主密码重置次数。
- 不会因输错主密码自动清除密码本、其他账号、备份或云端数据。
- 原生验证独立于界面串行执行、持久化失败次数并始终限速；拒绝非主窗口/非应用
  来源、超长输入及超限 KDF 参数。限速状态不随普通前端快照写入重置。
- 这不是硬件密钥库：已控制 WebView 的脚本、拥有本机文件权限的进程和离线猜测
  不在界面防护的信任边界内。强主密码、操作系统隔离和设备保护仍然必要。

## 本地数据库与备份

新数据库快照使用每次安装随机的 AES-GCM 密钥，文件为 `.workplan/.local-db-key`；
旧 WPDB1 数据和备份保留只读兼容路径，后续保存迁移至 WPDB2。
密钥丢失、损坏或不匹配时拒绝覆盖原数据库，不自动生成新密钥覆盖旧数据。

本机数据库及自动备份依赖此密钥。Unix 下目录收紧为0700、密钥为0600；Windows
依赖当前系统用户目录的访问权限。它不是对拥有该系统用户权限的进程的防护。
迁移整个 `.workplan` 目录时必须保护并同时迁移密钥，不能单独复制数据库。
旧版全球共用密钥加密的历史备份仍有原有风险，应以新备份替换并妥善处理旧副本。

侧边栏的加密备份仍然使用独立备份密码，跨设备可用。数据修复工具的数据库导出
也改为独立密码加密的可移植格式 WPBP2，需妥善保存备份密码。原生导入/导出命令
会在原生端弹出文件选择器，不接受脚本指定任意读写路径。

## 富文本与编辑器

AI/笔记 Markdown 的原始 HTML 按文本显示；最终输出统一净化，限制链接协议、
媒体 MIME 和可用样式，导出标题转义并附加 CSP。Mermaid 严格配置后的 SVG
以独立图片文档显示，不能向主界面注入 SVG/CSS。
Vditor 的不安全图表插件和原始 HTML 实时预览被禁用；源文本保留，公式和普通代码
仍可使用，阅读模式使用应用的安全图表渲染器。

允许的远程图片仍会发起普通网络请求，不应把净化器等同于“禁止一切异常请求”。
新增或升级第三方渲染组件时，仍需重复验证这些安全边界。
